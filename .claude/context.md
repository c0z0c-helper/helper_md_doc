# context.md (for Claude Sonnet 4.5)

## 0. 핵심 원칙
- 최신 정보 기준으로 작업
- 소스·문서는 매번 다시 읽고 판단
- 이모지·장황한 표현 금지
- `try/except` 금지, 오류 시 즉시 중단
- 요청 없는 문서화 금지

## 1. 개발 원칙
- MVP 최적화: 재현성(reproducibility) 우선
- 소스 기준: 구현·수정은 항상 `src/` 우선
- 소스 구조: 기능별 분리, 단일 파일은 가급적 `10K` 이하 유지
- 제안 단위: 함수·메서드·클래스 단위
- 코드 위치: 셀 번호 기준
- 출력 방식: `print` 최소화, 로깅 우선
- 길이 규칙: `20`라인 이하 즉시 제안, 초과 시 확인 후 진행
- 스타일: PEP 8, Black, isort, PEP 484, PEP 257, PEP 561 표준 규격 준수

## 2. 상호작용 프로토콜
1. 요구를 목표·제약·산출물로 요약
2. 접근 전략, 변경 파일, 영향 설명
3. 필요 시 진행 확인: “이 전략으로 진행할까요? (예/아니오/수정)”
4. 승인 후 최소 실행 예제 포함해 구현
5. 단문 또는 `20`라인 이하는 확인 생략 가능

## 2.1 작업 파일 운영 규칙
- 작업 문서는 `tasks/`에서 관리
- 설계·계획·체크리스트는 `task[번호].md` 형식 사용
- 각 파일은 핵심 내용 요약 + 진도 체크리스트 중심으로 구성
- `task` 설계 시 과도한 세부 코드 설계는 지양하고, 필요 시 개발에 필요한 정보만 추가
- 각 `task[번호].md`는 최대 `100`라인 이하 유지
- `100`라인 초과가 예상되면 설계·구현·검토를 분리해 다음 `task[번호].md`로 분할
- 개발 단계, 진행 상태, 다음 작업, 결정사항을 실시간 갱신
- 새 세션에서도 `task[번호].md`만 보고 바로 이어서 작업 가능해야 함
- 완료 시 `task[번호].md` → `task[번호]_done.md`로 변경, 원본 삭제
